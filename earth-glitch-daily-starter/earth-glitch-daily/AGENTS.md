# AGENTS.md — Earth Glitch Daily

> 本文件是 AI 與人類共同維護本專案的開發契約。任何新增、修改、重構，應先閱讀本文件。

## 1. 專案目標

- 網站名稱：每日一 BUG｜Earth Glitch Daily。
- 以繁體中文向一般讀者每天介紹 **一種真實存在、形態獨特的物種**。
- 每日一筆；以 `Asia/Taipei` 當地日期 (`YYYY-MM-DD`) 解鎖，不因重新整理或使用者裝置時區不同而提前解鎖。
- 可瀏覽過去公開的資料，未來日期的名稱與細節必須隱藏。
- 網站適合部署到 GitHub Pages，**不得要求後端、私鑰、付費服務**。

## 3. 視覺與互動規範

- 主題：深色自然科幻研究所（背景墨綠、螢光綠、青綠）。
- 字體使用系統字型，不依賴外部字型載入。
- 介面文案使用臺灣繁體中文，物種學名保留拉丁文。
- 重要內容需在手機與桌面都能閱讀；互動使用可聚焦的原生按鈕、輸入框和連結。
- 所有物種共用同一套圖鑑卡片和詳細檔案模板；**不得為新增單一物種建立新的 HTML 或 CSS 頁面**。
- 提供照片缺漏、API 失敗與排程空缺的可讀狀態；不得顯示壞圖或空白。

## 4. 每日物種資料格式

`data/species.json` 是按 `date` 升冪排列的陣列，每筆包含且只包含下列欄位（可新增欄位須先修訂本文件與驗證器）：

```json
{
  "date": "2026-12-13",
  "scientificName": "Glaucus atlanticus",
  "title": "大西洋海神海蛞蝓",
  "category": "海洋",
  "teaser": "一段簡短吸引人的介紹。",
  "feature": "一段可向可靠資料來源查證的形態特徵。",
  "bugRating": 5
}
```

- `date`：`YYYY-MM-DD`，必須是有效日期且不可重複。
- `scientificName`：iNaturalist 使用的有效物種層級學名（不是英語俗名）。不得重複；必須人工或自動核對 iNaturalist 的**精確學名**及物種層級。
- `title`：具可靠依據的臺灣繁體中文俗名；若無可確認的中文俗名，用學名，不可造假。
- `category`：限 `海洋`、`昆蟲`、`植物`、`真菌`、`哺乳`、`鳥類`、`爬蟲`、`兩棲`、`其他`。
- `teaser`：15–60 個中文字左右，以趣味語氣呈現；不可把想像當作生物學事實。
- `feature`：一個實際、具體且可追溯的特徵；不得無根據地描述危險性、棲地或保育狀態。
- `bugRating`：整數 1–5，**是網站娛樂性評分**，不可宣稱科學量測。
- 禁止加入未取得權利的相片、任意複製第三方全文、使用無來源的 AI 生成圖片冒充真實攝影。

## 5. 日期、解鎖與排程

- 唯一日期來源：`Intl.DateTimeFormat('en-CA', { timeZone: 'Asia/Taipei', ... })`。
- 精確匹配當日 `date` 顯示今日物種；未排程時顯示明確提示，**不得默默重播舊資料**。
- 歷史圖鑑公開 `date <= today` 的物種；未來資料只顯示「機密物種」，不洩漏名稱、學名或內容。
- 為避免提前發布，JSON **是公開可下載的靜態檔**，因此本專案的「鎖定」僅是前端 UI 展示，並非保密或存取控制。若未來需真正保密，必須使用逐日發布的 GitHub Actions 或後端。
- 每個日期只有一筆、物種不得重複；新增時延續既有日期、儘量保持連續。

## 6. iNaturalist 來源、照片與授權

- API 用於補足物種照片與來源，網站仍以 `data/species.json` 為每日介紹的穩定資料來源。
- 使用 `https://api.inaturalist.org/v1/taxa?q=<學名>&rank=species`，只接受**精確學名匹配**的 species 結果。
- 每個開啟中的詳細頁最多查詢一次相同物種，使用快取；避免每張卡片大量發送 API 請求。
- 只在圖片 `license_code` 明確屬於 `cc0`, `cc-by`, `cc-by-sa`, `cc-by-nc`, `cc-by-nc-sa` 時展示，並保留來源作者及授權文字。對 NC（非商業）圖片，只能在符合非商業條款的場景使用；不確定時停用該圖片。
- API 無回傳、查無精確學名、沒有合適圖片時，顯示自製替代圖與可供檢索的 iNaturalist 來源連結。不得無條件使用 `default_photo`。
- 不得直接把觀察資料授權與照片授權視為相同。若要下載或重新散布圖片，應重新審核使用授權及署名方式。
- iNaturalist 不背書本網站；資料介紹如涉及科學論述應另行驗證。
- API 呼叫速率遵循 iNaturalist 官方最新建議（約每秒一次，避免批量爬取）。

## 7. AI 新增物種的固定工作流程

1. 先閱讀 AGENTS.md、`data/species.json`、`scripts/validate.py`。
2. 指定新增日期，確認沒有衝突且該日期未被使用。
3. 從 iNaturalist 選擇真實物種，確認其為 species 階層並核對學名。
4. 排除既有 `scientificName` 重複項目，確認中文俗名與特徵正確。
5. 在 `data/species.json` 依相同欄位順序新增一筆，不改變既有紀錄與網頁結構。
6. 保持日期升冪排序，執行 `python scripts/validate.py`。
7. 在本機伺服器測試今日介紹、歷史圖鑑、篩選搜尋、詳細檔案，以及 API 失敗時畫面。
8. 在 PR 或提交訊息寫清楚新增日期、學名、資料來源、驗證結果。

## 8. 禁止事項

- 不可發明不存在的物種、學名或照片來源。
- 不可把「BUG 指數」描述成生物學指標。
- 不可因新增資料而手工複製物種 HTML 區塊。
- 不可上傳 API 金鑰、個人憑證，或在網頁中硬編碼機密資訊。
- 不可把 GitHub Pages 的前端解鎖誤寫成真正的資料保密。
- 不可未經確認就自稱已完成 GitHub 上傳或網站部署。
